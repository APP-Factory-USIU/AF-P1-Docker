PERSISTENT STORAGE

04 / YOUR TERMINAL

A few commands.
A working mental model.

Run these from the repository root.
Expand a command to understand every part.

STARTdocker compose up -d --build＋

docker is the CLI. compose manages the app in compose.yaml. up creates and starts services. -d runs them in the background. --build builds the custom image before starting. No service argument means both services.

INSPECTdocker compose ps -a＋

ps lists service containers and their status. -a means all, including stopped containers. Running is different from healthy: inspect the health status too.

WATCHdocker compose logs -f --tail 20 web＋

logs displays output. -f follows new output. --tail 20 starts with the last 20 lines per container. web selects the service. Press Ctrl + C to leave the log viewer; the services keep running.

LOOK INSIDEdocker compose exec redis redis-cli GET visits＋

exec runs a command in an existing container. redis selects the service. redis-cli is the program inside it. GET is a Redis command and visits is its key argument.

CLEAN UPdocker compose down＋

down stops and removes this project's service containers and network. It keeps the named volume and counter. Adding --volumes deletes the project's named volume and its data: use that only for a deliberate reset.

Changed the page? Run docker compose up -d --build again. A restart alone does not rebuild an image.
